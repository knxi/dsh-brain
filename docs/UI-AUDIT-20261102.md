# 全站审查与修复记录（2026-11-02）

> 起因：主人要「审查外置大脑的代码、逻辑、UI 是否漏了、UI 按钮重复等等」，之后说「修复」。
> 方式：三路并行只读审查（UI 逐页 / 前后端接口对账 / 后台逻辑缺口）+ 主线 11 页浏览器实测。
> 范围：`apps/brain-tools/` 11 个页面 + `packages/` 各模块后端 + 37 条 API 端点。

---

## 0. 结论先说

**没有真正的「按钮重复」问题。** 全站 20 个 `data-act`，重复的都只是列表渲染（一个候选一个按钮），
不是同一操作两个入口。真正的问题在别处，而且更严重：

1. **缺入口**（功能有后端、页面没按钮）
2. **说了假话**（页面文案和实现相反）
3. **静默失败**（失败了显示成功，或永远停在「载入中」）
4. **只增不删**（十几张表没有 TTL，outbox 已堆 1797 行）

## 1. 已修（8 项）

### 1.1 人格页：真发确认文案说反了 ⚠️ 最严重

`persona-page.js` 的「批准并发送」两步确认里写着「**不会发往任何第三方账号**」，
而 approved 分支实际走 `channelHook → dsh-im → 通道配置里的真实聊天目标`（当前配的是微信）。
**骗人骗在最重要的那一刻**：人正是看着这句话点的确认。

改成如实描述：会真的发出去、按现在的时间重过策略闸、经 dsh-im 投递到通道配置里的目标。

### 1.2 平台名混用（4 处）

默认通道值写「QQ 单聊」，生产 `channel.json` 配的是微信，页面上两套说法并存。
统一成中性表述「已配置的聊天通道」，不再写死任何平台。

### 1.3 人格页：写按钮失败后卡死

普通写操作（策略保存 / 通道保存 / 覆盖保存 / 冲突解决）失败后，按钮永久停在红色
「再点一次：X」状态——因为 `armed` 早被置 null，再点只是重新上膛，看着像按钮坏了。
其余三页（类脑 / 指令 / 空间）都有复位逻辑，唯独这页漏了。已补。

### 1.4 使用页：失败时永远「载入中…」

8 个区块都从同一个 `/api/usage` 取数，但失败时只清 1 个区块，其余停在 HTML 初始的
「载入中…」。人分不清「还在读」和「已经挂了」，会一直等。已改成一次性全部标「读不到」，
顶部数字一律回到「–」（不编 0）。

### 1.5 矛盾页：留痕失败不报

后端一直返回 `logged` / `loggedError`（注释还写着「必须如实说」），页面从来没读过。
于是「库改了、日志没写成」被渲染成一次干净的成功，而页脚还承诺「都留痕、都能撤销」。
已改成失败时明确追加「⚠ 留痕失败：…」。

### 1.6 矛盾页：空态暴露表名

空态写着「库里所有记忆之间都没有记过 contradicts。」——`contradicts` 是表字段名，
读页面的人不知道它指什么。改成「库里还没有任何一对记忆被判为互相矛盾。」
顺便把裸文本节点换成 `<span>`（`.empty span` 有 max-width 和居中约束，裸文本拿不到）。

### 1.7 人格页：25 条候选全平铺，14 条是死候选

今天落表的候选原来全平铺。实测 25 条里有 14 条已经 `rejected`，它们拿不到任何操作按钮，
只负责把页面拉长半屏。已改成：只列「等你处理的」，已结束的折进 `<details>` 默认收起，
标题写清「共 N 条，M 条等你处理」。

### 1.8 治理页：删除账本的「结果」列恒为「–」

页面读 `d.result`，但删除账本是 append-only 的审计链，条目里只有
「谁在何时申请删了什么、为什么、拿到哪张凭证」，**没有执行结果**。接口从来没返回过它。
已把这一列换成账本里真有的两个字段：**原因**、**凭证**；失去消费者的 `resultTag()` 一并删掉。

### 1.9 指令页：没有批准入口（功能缺失）

页面只有「全局暂停」和「切等级」两个按钮，**没有任何批准按钮**。而 `autonomy` 转出来的
指令一律是 `awaiting_approval` —— 于是系统会不停生成「我想做点什么」，主人却没有任何
地方能点头，指令永远跑不动。

已补：页面给 `awaiting_approval` 的行加「批准」按钮（两步确认）+
后端新增 `POST /api/directives/approve`（门面 `approve()` 自己严格校验状态）。

## 3. 未修（按危害排序，下次从这里接）

### 极高

**U1｜outbox 无消费者**
1797 行全部 `pending`、`attempts=0`、最早 10-28。生产代码零 `outbox.claim`，
`consumer_offsets` 表是 0 行。脑干已经判了 `outbox.backlog`，但 severity 只给 `low`。
删除闭环里的 `purge_tombstone` 永远完成不了。**要么接消费者，要么承认它是纯 log + TTL。**

**U2｜alert 通道整体没接**
`openBrain` 调用没传 `alert` → 所有 `alert(...)` 出口都是空操作。
这不是某个 catch 写错，是「静默失败」被设计出来了：调度器崩溃、社交发送失败、
免疫隔离——全部无声。

### 高

**U3｜social.expire() 无调用者**（今天管道被堵死的根因）
过期候选永久占 `max_pending` 名额。今天靠人工取消才解开，但会复发。
挂进 `driveSocial` 每轮开头即可。

**U4｜删除记忆无等级、无确认词**（前一份 PERMISSION-AUDIT 的 P1-1，仍未修）

**U5｜reflections 22 条 candidate 没有自动出口**
自动晋升只认 `contradiction`，而这 22 条全是 commitment / knowledge_gap / pattern，
永远等不到人，还占着 `list({limit:50})` 的名额。

### 中

**U6｜十几张表只增不删**：`events`(1788) / `audit_logs`(67) / `social_candidates`(39) /
`social_sends`(13) / `reflection_runs`(21) / `directive_steps`(6) / `ws_events`(5) /
`fox_events`(101) / `sessions`(20)。全仓没有任何 TTL / 归档 / VACUUM。

**U7｜三个「有实现、无调用者」**：`pruneEvents`（mood.js）、`pruneBackups`（backup.js，
 backups 目录已 39MB）、`reclaimExpired`（candidates.js）。

**U8｜孤儿数据**：`memory_versions` 5 条指向已删记忆；`entities` 10 个无引用。

**U9｜`/api/conflicts/action` 内联复制了一份同源校验**，没走 `jsonAction`。
保护强度等价，但改一处会漏另一处。

**U10｜4 条孤儿 API**：`GET /api/{workspace,cognition,persona,directives}` 是页面的 JSON 镜像，
没有任何消费者（验证脚本也不碰）。要么登记用途，要么删。

### 低（体验/文案）

- 回首页 3 种叫法：「回列表」「回记忆」「回记忆控制台」
- 「同源」说法错误：记忆页说治理面板「同源，点开就能用」，实际是 302 跨端口到 7420
- 两步确认时限不统一：3 秒 / 4 秒
- 实体页/心情页各有一处 `**加粗**` 原样显示星号（Markdown 语法进了 HTML）
- 心情页 `#orbit-tip` / `#orbit-empty` 是死元素
- 心海页顶部「神经元」用全量、底部「活动节点」用可见量，筛选后两个数字对不上
- 心海页「只看最近」硬编码 120 条上限，页面没说
- 矛盾页 `CONFIRM_TTL=3000` 偏短，确认提示有 5 行

## 4. 这次被抓出来的两个方法论教训

1. **渲染态和 textContent 不是一回事。** 我用 `element.textContent` 读空态，得出
   「两句话粘在一起」的结论——实际 `<strong>` 是块级元素，渲染出来是分行的。误报。
2. **主模块改动不能拿运行中的服务验证。** 改完 `index.js` 立刻打接口，测的是旧代码，
   还因此误晋升了一条记忆（已清理）。要先确认进程启动时间早于文件改动时间。
