# 第一部分 · 设计说明

## 1. 它到底要解决什么

**有效上下文扩展，不是上下文窗口扩展。**

模型聊到十万字之后会忘记早期的约定。主流解法是塞更长的历史（窗口扩展）。这个项目选了另一条路：**把记忆落到本地 SQLite，需要的时候检索出来**（有效上下文扩展）。

原设计的母本是《DSH外置大脑-可执行设计方案-v1.2》第 21、22 节，`CONTRACTS.md` 只摘了实现必需的部分。

**它要替换什么**：Engram 和灵枢两个现有记忆插件。目标是「能卸掉它们」。
**卸不掉的两个硬条件**（ROADMAP 明写）：
1. 自动提取能力 —— 外置大脑原先是 explicit 模式，主人不说「记住」它就不记
2. 观察期样本 —— 迁进来的记忆要实际用几轮，看检索到底准不准

## 2. 分层结构

```
DSH 会话 / 模型
   │
   ├─ ① 显式：brain_search / brain_remember / brain_forget
   └─ ② 自动：connector 挂 5 个装配点注入
                │
                ▼
   context      检索 → 构包 → Token 预算 → built/attached/sent 三级证据
                │
                ▼
   search       FTS5 char-space（主）+ trigram（补）+ n-gram（兜底）→ RRF 融合
                │
                ▼
   memory       唯一写入通道：单写入队列 / 事务 / outbox / 幂等 / 删除屏障
                │
                ▼
   brain.db     SQLite WAL
```

外加三个方向（M8）：`workspace`（事件总线）+ `cognition` / `persona` / `directives`。

## 3. 偏离项 A：M5 自动提取提前启动

ROADMAP 原文（行 92-93、107、174）三处强调：

> Phase 2 的前置：观察期数据够（**≥20 次检索** + 引用率有基线）
> **不在观察期没跑够之前做自动提取** —— 会把「检索本来就不准」和「自动提取污染了库」两件事混在一起，事后分不清

实际：**Phase 1（规则型）已交付**，`apps/brain-tools/auto-extract.js` + 23 条测试。

**但这一条我要给项目方辩护一半**：
- 交付的是 **Phase 1 规则型**，不是 Phase 2 模型语义提取。规则型是「记住/以后都用/改成」这类显式句式，用四道闸（疑问/假设/转述/否定/反讽）先过滤，实测四个回合只有 1 个命中。
- 契约 §20 写了配额（每轮 1 / 每会话每天 5 / 全局每天 20）+ 开关 + 失败静默。
- 且**明确不调模型**（Brain 自身不发 LLM 请求）。

**判定**：文字上违反「不要提前做」，实质上做的是风险最低的那一档，且有硬配额。**属于可接受的抢跑，但 ROADMAP 没有同步更新这一条，造成文档自相矛盾**——文档说「不做」，代码里做了。

### 4.2 它的「合法性」

M8 **不是无设计地乱加**，有两份独立契约：

- `docs/SYSTEM-3456-CONTRACT.md` —— 并行施工契约，含「目录所有权（硬边界，越界即返工）」「默认安全姿态（不许商量）」
- `docs/SYSTEM3-COGNITION.md` / `SYSTEM4-PERSONA-SOCIAL.md` / `SYSTEM5-DIRECTIVES.md` —— 每份都有「**明确不做什么**」「**怎么关掉**」「**已知缺口**」三节

`docs/M8-SYSTEMS-3456.md` 开篇结论：

> 四套系统**都已经在磁盘上、在生产库里、在测试覆盖里**，但**默认全部关闭**。
> 这不是没做完，是刻意的：自主行为、主动社交、外发消息这三件事，第一次必须由你亲手打开。

### 4.3 但它是路线偏离 —— 三个理由

**理由一：ROADMAP 从没规划过它。**
ROADMAP 的优先级排序逻辑是「按「能卸灵枢」这条路排」。系统 3/4/5/6（类脑协同 / 人格社交 / 自主指令 / 治理可视化）**和「卸掉灵枢 Engram」没有直接因果关系**。它们是在解另一个问题——「让这个 AI 有自己的状态、主动性和社交」。

ROADMAP 行 170-174 的「明确不做的事」四条，M8 一条不违反，但 M8 **也不在那四条覆盖的范围内**——它是计划外的第五件事。

**理由二：它抢的是观察期的时间。**
ROADMAP 行 176-179：

> **现在要做的唯一一步**：把它用起来，让样本长到 20 次以上。
> 2026-10-29 夜实测：7 天窗口内只有 **1 次**检索。
> 卡着观察期的**不是功能，是使用**。

这句话写完之后，落地的**全是功能**。

**理由三：默认全关 = 投产价值为零。**
四套系统 292 项测试全绿、26 张表全建好，但开关默认关着。当前生产库实测：

## 6. 守得住的部分（客观记录）

不能只列问题。以下这些是**明确做对且少见的**：

**① 三级证据边界被执行成了硬约束。**
`built` / `attached` / `sent` 三级不混用，且「没有请求边界证据时禁止声称 sent」。这是防止「假装注入成功」的关键设计，代码里真的在分。

**② 拒绝用代理指标凑数。**
`usedLater`（检索命中是否真的被回答用上）判据定为「连续 ≥12 字原文」，做不到就返回 `null`，不拿别的指标代替。ROADMAP 原话：「猜出来的数比没有数更糟」。

**③ 统计口径被踩过两次坑并写进契约。**
- 失败检索不计入「零命中」（否则零命中榜全是故障）
- 缺字段保持 `null` 不落成 `0`（`Number(null)===0` 会让 null 耗时混进 p50/p95）

**④ 11 条实测修正单独成节（§10–§20），优先级高于原始契约。**
文档里明文写着「**不信文档，信实验**——这项目里至少有 5 个地方，文档写的东西和实机行为对不上」。

**⑤ 默认安全姿态。**
M8 四系统全部默认关；矛盾「并列保留、绝不自动选边」；合并走 `supersedes` 不删正文；跨 scope 拒绝建关系。

**⑥ 每做一次数据变更都留回滚。**
`MERGE-ROLLBACK-20261030.sql`、`fix-entity-kinds --apply` 幂等复跑、`0008.down.sql`。

**⑦ 全量测试本次真跑通过。**

## 8. 审计结论

### 一句话

**这不是「设计走偏」，是「施工节奏走偏 + 契约文档失修」。**

### 三条判断

**判断一：技术骨架没坏。**
§0 的六条工程决策全部兑现，三级证据、单写入通道、删除屏障这些关键约束一个没松。**换个人接手，底座是能用的。**

**判断二：功能边界扩张缺乏 ROADMAP 授权。**
M8 的 26 张表 + 15,532 行代码，不在任何版本的路线图里。它有自己的契约、自己的一致性、自己的安全姿态——**唯一缺的是「为什么现在做它」这一句**。

**判断三：最贵的资产没在产生价值。**
项目自己判定「最值钱的是 §10/§11/§12 那 28 条实测约束」。但生产库里 226 条记忆，近 7 天检索 1 次。**数据管道通了，样本没长起来。**

### 建议（按优先级）

| 优先级 | 动作 | 理由 |
|---|---|---|
| **P0** | 把母本 v1.2 找回或重写一份进 `docs/` | 现在审计只能靠二手摘录，盲区已实证存在 |
| **P0** | 更新 `CONTRACTS.md` §1 包边界表与 §4 表清单到 51 表 / 11 目录现状 | 文件自称「全队对齐依据」，现在对不上 |
| **P1** | 在 ROADMAP 里补一条 M8 的立项理由，或明确写「暂缓」 | 消除「文档说不做、代码里做了」的矛盾 |
| **P1** | 决定 M8 四系统是否要开一个最小开关跑真实数据 | 292 项测试全绿但生产痕迹为零，等于没有验证 |
| **P2** | 回到观察期：把 `brain_search` 用起来，样本到 20 次再看结论 | ROADMAP 自己判定的唯一一步 |
| **P2** | 界定红线 3 的「迁移」含义 | 现在 Engram 导入处于合规灰区 |

## 9. 给审计者的提醒（项目自己的话）

HANDOVER.md 留给接手人四句话，原样抄录：

1. **先看 `docs/CONTRACTS.md` 第 10、11、12 节**。那 28 条实测约束是这个项目最贵的东西，绕过去就会重新踩一遍。
2. **不信文档，信实验**。这项目里至少有 5 个地方，文档写的东西和实机行为对不上（hook 名、注入形态、隔离边界、FTS 语法、createdAt）。
3. **数据比代码重要**。改代码最多是功能坏掉，动 `data/brain.db` 或 `data/deletion-ledger/` 可能让已经删掉的东西复活。
4. **观测数据本身也会说谎**。`Number(null)===0`、失败检索混进零命中、路由前缀切错位——这三样**都不报错**，只是数字悄悄变错。看任何统计之前，先读它的口径。
