# 人格页顶部的状态变成可控开关（2026-10-31）

## 需求

`/dsh-brain/persona` 顶部那排「全局暂停 关 / 主动社交 开 / 允许外发 开 / 外发能力 有」
原来是**只读 chip**，主人要在页面上直接点着切。

## 做法

### 1. 三个开关

| 按钮 | 切换的键 | 说明 |
|---|---|---|
| 全局暂停 | `paused` | 最高优先级：一开所有自主模块停手 |
| 主动社交 | `social.enabled` | 关掉后不再生成候选、也不发送 |
| 允许外发 | `social.allow_external` | 关掉后只能 dry_run，批准也不会真发 |
| 外发能力 | —（只读） | 取决于通道有没有配，不是开关 |

实现要点（`apps/brain-tools/persona-page.js`）：

- 新增模块级 `switchChip(name, label, on, hint)`：按钮上显示**当前状态**，
  `data-next` 带的是「点完之后的值」。放在模块级是因为**顶部状态条**和
  「主动社交」卡片两处都要用。
- 写操作复用现成的 `POST /dsh-brain/api/workspace/switch`（同源保护 + 审计），
  不是新造一套状态。
- **两步确认**复用页面里已有的 `armed` 机制：第一次点只把按钮改成
  「再点一次：X 开/关」，4 秒不点自动退回；第二次才真发请求，成功后刷新页面。
- 失败走已有的 `errBox()` 显示原因，不静默。

### 2. 顺带修正的过时文案

通道从 console 换成 QQ 之后，页面还写着「批准发送只到本机 console」，共 4 处，全部改成如实描述：

| 位置 | 改后 |
|---|---|
| 候选卡片右上角 | 预演只读 · 批准发送走 QQ 单聊（dsh-im 主动投递） |
| 页脚说明 | 过了才经 QQ 单聊通道发给你本人；通道失败会回落本机落盘并**如实报错** |
| 发送成功提示 | 已通过 QQ 单聊发出（dsh-im 主动投递） |
| `/api/persona/social/send` 的 note | 同上口径 |

同时把 `social.send()` 的 `channel` 从 `'console'` 改成 `'qq'`：这个值会写进
`social_sends` 记录，写 `console` 会让人以为走的是本机落盘。

## 仍需重启

`persona-page.js` 是服务端渲染模块，当前 3080 加载的还是旧版本；**重启后生效**。

## 没做（要的话说一声）

「策略」那行仍然是只读：`enabled / dailyCap=2 / cooldownMinutes=180 / maxPending=1 / quietHours=[]`。
这些是**数值**不是开关，要做成可调得加一个策略编辑接口（`persons.updatePolicy` 已经支持，
只差页面表单）。要不要做，你定。
