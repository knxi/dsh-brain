# 心海：点星聚焦后不在屏幕中心（2026-10-31 修）

## 症状

点一颗星 → 镜头拉近、其他星淡出，但**被点的星不在视口中心**，偏右上（截图里偏到 2/3 处）。

## 根因

`apps/brain-tools/sea-page.js` 的 `enterFocus()` 原来只做：

```js
camTarget.panX = -p.x
camTarget.panY = -p.y
```

注释写的是「近似，z 旋转仍有残余偏移，但够用」。**实际不是够用**：`project()` 里世界坐标要过两道旋转——

```
x1 = wx·cos(yaw) − wz·sin(yaw)
z1 = wx·sin(yaw) + wz·cos(yaw)
y1 = wy·cos(pitch) − z1·sin(pitch)
```

只把 pan 设成 −point 等于让 `wx = wy = 0`，此时

```
x1 = −wz·sin(yaw)     ← 只要 wz ≠ 0 就不为 0
y1 = −wz·cos(yaw)·sin(pitch)
```

**偏差与点的 z 成正比**。默认视角 `yaw=0.45 / pitch=−0.30` 下，实测最坏偏 **4400px**（点直接被甩出屏幕），典型点偏几百 px。

## 修法（解析解）

令 `x1 = 0` 且 `y1 = 0`，解出唯一的一组 `(wx, wy)`：

```
wx = wz · tan(yaw)
z1 = wz / cos(yaw)
wy = z1 · tan(pitch)
```

再反推 `panX = wx − p.x`、`panY = wy − p.y`。

两个实现细节：
- 用 **`camTarget` 的 yaw/pitch** 算（聚焦不改这两项，插值到位后的最终视角就是它们）；拿 `cam` 当前值算会在动画途中偏掉。
- `dist` 不参与：`x1 = y1 = 0` 时屏幕坐标恒为视口中心，与焦距无关。

## 验证

### 1. 纯数学（4 个不同量级的点，视口 1893×905）

| 点 (x,y,z) | 旧公式偏移 | 解析解偏移 |
|---|---|---|
| (1200, −400, 700) | 350 px | **0.00 px** |
| (−300, 900, −1100) | 4407 px | **0.00 px** |
| (0, 0, 0) | 0 px | **0.00 px** |
| (800, 200, −300) | 642 px | **0.00 px** |

### 2. 真机（临时服务渲染新页面 + `?debug` 钩子，225 颗星，视口 1400×961）

点 3 颗不同的星，用**页面自己的 `project()`** 量位置：

| 星 | dx | dy |
|---|---|---|
| c82b7d48 | 0.63 | 4.34 |
| 44cbbb83 | 6.11 | −9.01 |
| e3f43969 | −2.44 | 10.30 |

> 这几像素不是公式误差，是**指数缓动还在收敛**（相机 320ms 时间常数）。同一颗星按时间采样：
>
> | 等待 | dx | dy |
> |---|---|---|
> | 400ms | 83.2 | −55.2 |
> | 800ms | 34.7 | −23.0 |
> | 1200ms | 11.6 | −7.7 |
> | 2000ms | 0.96 | −0.64 |
> | **4000ms** | **0** | **0** |

即：动画走完就是**精确居中**，慢的那几像素是「不硬」动效的代价（README 里明确设计过 320ms 缓动）。

## 顺带加的调试钩子

`window.__sea.projectOf(id)`（只在 `?debug` 时暴露）：用页面自己的 `project()` 返回某颗星的屏幕坐标和 `dx/dy` 距中心差。以后「点星是否居中」可以自动化验收，不靠肉眼看截图。
