## 0. 结论先行

**功能基本不缺，缺的是「用」。**

1. **齐全度：低估了。** 文档说「五个视图、三个工具」，实际是 **11 个页面 + 27 个 API + 3 个工具 + 2 个会话钩子 + 一个进程内治理服务（7420，16 路由）**，前端 fetch 与后端路由双向差集为 0——**零坏链、零死路由**。989 个测试里 988 绿。
2. **有用性：很不均。** 真正在产生价值的只有一条最短链路：**218 条记忆 → 13 次检索 → 3 条被证实被回答引用**。218 条里有 178 条从没被任何一次检索命中（覆盖率 18.3%），且 205/226 条是 10-29 从 Engram 迁进来的旧数据；本系统自己写入的 13 条停在 46 小时前。
3. **最难受的是「中间态」。** 三处功能处在最差状态——有代码、有页面、有开关，但零产出：自动提取（挂了但从没跑过，日志文件都不存在）、M8 四套系统（开关已全开，但**没有任何驱动器**：packages 与 brain-tools 全文无定时器，20 张 M8 业务表全 0 行，仅 `person_models` 等 3 张各 1 行来自 `init-person` 冷启动）、冲突核验（0 条边可核验）。

一句话：**代码层面「做完了」，使用层面「还没开始」。**

## 7. 处置建议（按性价比排序）

**P0 · 该修，单点小改**
1. ~~`usage-page.js:315` 单引号~~ —— **已核实是误判**（外层模板串会插值），已改成显式拼接消除歧义（`fix-页面修复.md`）。
2. 测试改成读运行时版本：`assert.equal(inspected.sqlite_version, db.prepare('SELECT sqlite_version() AS v').get().v)`。
3. `brain_remember` / `brain_forget` 补 `recordUsage`（和 search 同一个 `finally` 口径），否则「写了几次、忘了几次」永远只能靠倒推。
4. 跑一次 `deletion-worker` 把 `brain_forget` 卡住的 5 个 pending job 清完——**现在被删的记忆还在 FTS 里能搜到**，这是删除承诺的实质违背。

**P1 · 先决定「接」还是「关」，别留在中间态**
5. **自动提取**：要么按 ROADMAP Phase1 真正打开观察（先确认它为什么 0 次触发——`turn/end` 的 `reason.kind` 判据、配额、规则是否都可能导致永远不命中），要么 `config.autoExtract: false` 明确关掉。挂着不工作是当前最糟的状态。
6. **M8 四系统**：`publish / propose / runOnce / checkOnce / generate / arbitrate / send` 这些入口**在生产没有任何驱动器调用**（packages 与 brain-tools 全文无定时器）。要么补一个调度器把它们跑起来，要么把开关退回默认全关并写清「暂不启用」——现在开关全开、页面全活、数据全空，只会让人误判。
7. **冲突能力**：`conflict-actions` 改成「先留痕再删边」（记 from/to/kind），否则处理完就再也回看不出原本矛盾的是什么。

**P2 · 清理维护负担**
8. `governance-page.js`（699 行、永不渲染）——保留但显式标注为降级兜底，或删掉。
9. 11 页内联 CSS 收进 `nav.js` 的共享样式（68 KB 重复）。
10. README / ROADMAP / M8 文档的数字对齐（视图数、测试数、记忆数、开关默认值）。
